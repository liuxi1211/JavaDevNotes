
## 一、知识库架构层级：四层双轨隔离架构

### 核心设计原则

- **双轨并行**：公司级知识库仅存跨团队共享知识，系统内部知识全部存放在各自代码仓库
    
- **权限隔离**：不同角色只能访问自己需要的知识层级
    
- **AI 优先**：所有文档格式和内容以机器可理解为第一原则
    
- **自动化优先**：90% 内容通过 CI/CD 自动生成，仅 10% 需要人工编写

|---|---|---|---|---|---|---|
|层级|名称|存放位置|可见范围|维护方|核心内容|AI 加载策略|
|L0|公司全局知识库|独立 Git 仓库：`company-knowledge-base`|全公司可见|架构组|编码规范、通用组件、公共服务、架构决策、开发流程|全局默认加载|

## 三、知识库动态维护机制

### 1. 自动化维护流水线（90% 内容自动更新）

#### 1.1 接口文档自动同步

- **触发时机**：每天凌晨 2 点 + 微服务发布到生产环境时
    
- **执行流程**：
    
    - CI/CD 流水线调用`openapi-to-markdown`工具
        
    - 拉取各微服务最新的 Swagger/OpenAPI 文档
        
    - 自动更新 L1 层文档中的接口部分（保留人工编写部分）
        
    - 自动提交 PR 到`domain-knowledge-base`仓库
        
    - 自动合并 PR（无需人工审核）
        
- **GitLab CI 配置示例**：
    

```yaml
stages:
  - sync-docs

sync-docs:
  stage: sync-docs
  image: python:3.11
  script:
    - pip install requests pyyaml jinja2
    - git clone https://git.company.com/architecture/domain-knowledge-base.git
    - cd domain-knowledge-base
    - python ../scripts/openapi_to_markdown.py
    - git config user.name "CI Bot"
    - git config user.email "ci-bot@company.com"
    - git add .
    - git commit -m "Auto update interface docs" || exit 0
    - git push origin main
  only:
    - schedules
    - tags
```

#### 1.2 枚举和错误码自动同步

- 开发 Maven/Gradle 插件，在编译时自动扫描项目中的枚举类和错误码定义
    
- 生成对应的 Markdown 文件，提交到微服务的`/docs`目录
    
- 全局枚举自动同步到 L0 层的`06-global-enums`目录
    

#### 1.3 文档质量自动检查

- 每天运行一次 Claude Code 文档质量检查任务
    
- 检查内容：接口完整性、代码示例正确性、过时内容、拼写错误
    
- 生成质量报告，发送给对应服务负责人
    

#### 1.4 文档过期自动清理

- 为每个文档添加`last-updated`标签
    
- 自动检查超过 6 个月未更新的文档
    
- 提醒负责人确认有效性，无效则自动归档

## 四、知识库与 Claude Code 集成使用指南

### 1. 知识库挂载方式

#### 1.1 全局挂载

- 在 Claude Code 企业管理后台，将 L0 层和 L1 层 Git 仓库挂载为全局知识库
    
- 配置自动同步：每小时拉取一次最新代码
    

#### 1.2 仓库级挂载

- 每个微服务代码仓库的`/docs`目录和`CLAUDE.md`文件会被 Claude Code 自动识别并加载
    
- 无需额外配置，只要开发者克隆了仓库，Claude Code 就能访问这些内容
    

#### 1.3 权限控制

- 在 Claude Code 后台配置 L1 层各业务域的访问权限
    
- 敏感服务（如支付、风控）的 L1 层文档需要单独申请权限
    
- L2 和 L3 层的权限由 Git 仓库的权限自动控制
    

### 2. AI 检索优先级配置

在 Claude Code 后台设置以下检索优先级（从高到低）：

1. 当前仓库的`CLAUDE.md`文件（L3 层）
    
2. 当前仓库的`/docs`目录下的所有文件（L2 层）
    
3. L0 层公司全局知识库
    
4. L1 层当前业务域知识库
    
5. L1 层其他业务域知识库（需要明确指定）

## 六、常见问题解答

### Q: 为什么不用 Confluence 作为知识库？

A: Confluence 的富文本格式 AI 解析准确率低，版本控制能力差，自动化能力弱。纯 Markdown+Git 是目前 AI 友好性最好的方案。

### Q: 如何防止知识库信息泄露？

A: 通过 Git 仓库的权限控制和 Claude Code 的访问权限控制，确保敏感信息只能被授权人员访问。

### Q: 文档更新不及时怎么办？

A: 90% 的内容通过自动化同步保证实时性，人工部分通过绩效考核和巡检制度保证更新及时。

### Q: 开发人员不愿意写文档怎么办？

A: 尽量减少人工编写的工作量，只要求编写 10% 的核心内容。同时将文档贡献纳入绩效考核，建立奖励机制。
