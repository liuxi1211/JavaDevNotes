
## 一、什么是上下文？

**上下文 = OpenClaw 每次回复你时，一次性发给 AI 模型的所有内容**。它有一个硬性上限，就是模型的 "上下文窗口"（用 token 数量计算，1 个 token≈4 个汉字）。

简单理解，上下文就像 AI 的 "临时笔记本"，它只能看到这个本子上写的内容，本子写满了就记不住新东西了。

⚠️ **上下文 ≠ 记忆**

- 上下文：AI 当前能看到的临时内容，窗口满了就会被挤掉
    
- 记忆：存在电脑磁盘上的永久内容，可以随时重新加载到上下文里
    

上下文主要由三部分组成：

1. **系统提示词**（OpenClaw 自动生成）：AI 的规则、能用的工具、技能列表、当前时间、你的工作区文件等
    
2. **对话历史**：你发的消息 + AI 之前的回复
    
3. **工具调用和附件**：AI 执行命令的输出、读取的文件内容、你上传的图片 / 音频等
    

## 二、5 个快速检查上下文的命令

直接在聊天框输入这些斜杠命令，就能查看上下文状态：

|   |   |
|---|---|
|命令|功能|
|`/status`|快速看 "上下文窗口用了多少" + 当前会话的基本设置|
|`/context list`|列出所有自动加载的内容 + 每个文件的大小 + 总大小|
|`/context detail`|超级详细分解：每个文件、每个工具、每个技能、系统提示词各自占了多少 token|
|`/usage tokens`|开启后，AI 每次回复都会在末尾显示这次用了多少 token|
|`/compact`|把较早的对话历史总结成简短的一句话，释放上下文空间|

## 三、到底什么会计入上下文窗口？

**所有发给模型的内容都算**，包括你看不到的部分：

1. 完整的系统提示词（所有组成部分）
    
2. 所有对话历史
    
3. AI 调用工具的请求 + 工具返回的结果
    
4. 你上传的所有附件（图片、音频、PDF 等）
    
5. 用`/compact`生成的压缩摘要
    
6. 模型提供商偷偷加的 "包装内容"（你完全看不到，但确实占 token）
    

## 四、OpenClaw 的系统提示词是怎么组成的？

系统提示词是 OpenClaw 每次运行时自动生成的，你不能直接修改，但可以通过修改工作区文件间接影响它。

它包含以下内容：

- 所有可用工具的名称和简短描述
    
- 所有可用技能的名称、描述和位置
    
- 你的工作区文件夹路径
    
- 当前时间（UTC 时间 + 你设置的本地时间）
    
- 运行环境信息（你的操作系统、用的什么模型等）
    
- 自动加载的工作区引导文件内容
    

## 五、自动加载的工作区文件

默认情况下，OpenClaw 会自动查找并加载你工作区里的这 7 个文件（如果存在）：

- `AGENTS.md`：代理配置
    
- `SOUL.md`：AI 的性格设定
    
- `TOOLS.md`：自定义工具
    
- `IDENTITY.md`：AI 的身份设定
    
- `USER.md`：你的个人信息
    
- `HEARTBEAT.md`：心跳配置
    
- `BOOTSTRAP.md`：启动配置（只在第一次运行时加载）
    

⚠️ **大文件会被截断**：单个文件超过 20000 字符时，只会加载前 20000 字符。`/context list`会显示 "TRUNCATED" 标记，告诉你这个文件被截断了。

## 六、Skills（技能）是怎么加载的？

技能不会一次性全部加载到上下文里，这样太浪费空间了：

- 系统提示词里只包含一个**技能目录**：技能名称 + 一句话描述 + 文件位置
    
- 当 AI 需要使用某个技能时，它会自己去读取对应的`SKILL.md`文件内容
    
- 这样平时上下文里只有几十到几百字符的技能目录，而不是几 MB 的完整技能代码
    

## 七、工具的两种上下文成本

工具是上下文消耗的大户，它以两种方式占用空间：

1. **工具列表文本**：系统提示词里的 "可用工具：read, edit, write..."，这部分你能看到
    
2. **工具功能定义（Schema）**：JSON 格式的详细说明，告诉模型这个工具怎么用、需要什么参数。这部分你完全看不到，但占的空间通常比工具列表大得多！
    

用`/context detail`可以看到哪个工具的功能定义占空间最多，比如浏览器工具通常是最大的。

## 八、斜杠命令和指令的处理

不是所有你发的消息都会进入上下文：

- **独立命令**：只输入`/status`、`/context list`这样的纯命令，不会进入对话历史
    
- **全局指令**：`/think`、`/verbose`、`/model`这些指令，会在模型看到消息之前被剥离，但会保存为会话设置
    
- **内联指令**：比如 "帮我写个 Python 脚本 /verbose"，`/verbose`会被剥离，只把前面的内容发给模型
    
- **内联快捷方式**：比如 "hey /status"，`/status`会先执行，然后把结果和剩下的文本一起发给模型（只有白名单用户能用）
    

## 九、会话、压缩和修剪的区别

这三个都是管理长对话的方式，但效果不同：

- **正常会话**：所有消息都完整保存，直到上下文满了
    
- **压缩（/compact）**：把较早的几条消息总结成一句简短的话，保存到会话记录里，最近的消息保持不变
    
- **修剪（Prune）**：从上下文里删除最旧的工具结果，但不会修改会话记录。下次打开会话时，这些工具结果还会重新加载
    

## 十、/context 命令实际报告什么？

`/context`命令不会显示完整的系统提示词或工具定义，只会显示大小统计：

- `System prompt (run)`：从最后一次有工具调用的运行中捕获的实际系统提示词大小（最准确）
    
- `System prompt (estimate)`：如果还没有运行过，就估算一个大小
    

它会告诉你上下文的主要 "消耗大户" 是谁，帮你找到可以优化的地方。
