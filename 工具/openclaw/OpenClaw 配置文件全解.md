
OpenClaw 所有配置与状态数据默认存储在**用户主目录下的** **`~/.openclaw/`** **目录**（也叫 State Directory，状态根目录），可通过 `OPENCLAW_STATE_DIR` 环境变量自定义路径。其配置体系遵循「全局核心配置 + 工作空间行为定义 + 专项功能配置」的三层架构，所有配置均支持纯文本编辑，无需专有工具。

## 一、核心全局配置文件（根目录核心）

这是 OpenClaw 网关启动的核心依赖，决定系统级的基础能力、接入规则与安全策略。

|   |   |   |   |
|---|---|---|---|
|文件路径|格式|核心作用|关键说明|
|`~/.openclaw/openclaw.json`|JSON5（支持注释、尾随逗号）|系统**主配置文件**，是所有配置的总入口，包含网关、模型、渠道、Agent、工具、插件、安全等全量顶级配置项|1. 首次运行自动生成，无该文件时系统使用安全默认值启动； 2. 配置加载优先级：`--config` 命令行参数 > `OPENCLAW_CONFIG_PATH` 环境变量 > 默认路径； 3. 大部分配置修改后支持**热重载**，网关会自动监听文件变更并生效，核心网络 / 进程配置需重启网关； 4. 内置严格的 Schema 校验，非法字段 / 格式错误会导致网关拒绝启动|
|`~/.openclaw/.env`|dotenv 格式|敏感凭证与环境变量配置文件，用于存放模型 API Key、渠道令牌、加密密钥等敏感信息，避免硬编码到主配置中|1. 可选文件，不会随安装自动生成，需手动创建； 2. 支持在 `openclaw.json` 中通过 `${VAR_NAME}` 语法引用该文件中定义的变量； 3. 不会覆盖系统已存在的环境变量，仅做兜底补充|
|`~/.openclaw/secrets.json`|JSON|加密凭证存储文件，用于存放 OAuth 令牌、渠道加密凭证等敏感数据|1. 系统自动生成与管理，不建议手动编辑； 2. 区别于 `.env`，该文件用于存储运行时动态生成的加密凭证，而非手动配置的静态密钥|

## 二、Workspace 工作空间配置文件（Agent 灵魂定义）

工作空间是 OpenClaw Agent 的核心行为定义目录，默认路径为 `~/.openclaw/workspace/`，可在主配置中通过 `agents.defaults.workspace` 自定义路径。该目录下的所有 Markdown 文件会在 Agent 启动时自动加载，直接决定 Agent 的身份、性格、能力边界与工作规则，是实现个性化智能助理的核心配置。

|   |   |   |
|---|---|---|
|文件路径|核心作用|关键说明|
|`workspace/SOUL.md`|Agent 人格与性格设定，定义「你是一个什么样的助手」|核心配置，决定 Agent 的回复语气、风格、价值观、对话习惯，比如严谨专业 / 活泼口语 / 极简高效等风格，是 Agent 人设的核心载体|
|`workspace/USER.md`|用户信息配置，定义「你在为谁服务」|写入用户的个人信息、偏好、工作场景、常用需求，让 Agent 更贴合用户的使用习惯，实现个性化服务，避免重复交代背景信息|
|`workspace/IDENTITY.md`|Agent 身份标识配置|定义 Agent 的名称、对外称呼、头像、标识 emoji 等视觉 / 身份信息，用于多渠道展示与多 Agent 区分|
|`workspace/AGENTS.md`|Agent 工作手册与行为规则，核心系统提示词载体|定义 Agent 的核心职责、任务执行流程、工具使用规则、安全边界、多渠道回复规范、触发式行为，相当于 Agent 的岗位说明书，直接决定 Agent 的任务执行能力上限|
|`workspace/BOOT.md`|启动提示词配置|Agent 网关启动时自动加载的提示词，可定义启动后自动执行的初始化任务、自检流程、全局规则，是 Agent 开机自启能力的核心配置|
|`workspace/MEMORY.md`|手动长期记忆配置|可手动编辑的全局长期记忆，写入需要 Agent 永久记住的关键信息、规则、历史事项，跨会话生效，不会随对话上下文清空|
|`workspace/HEARTBEAT.md`|心跳 / 定时任务检查清单|定义 Agent 周期执行的心跳任务、每日 / 每小时检查清单、定时巡检规则，配合主配置的 cron 能力实现主动自动化任务|

## 三、专项功能配置目录与文件

这类配置用于扩展系统能力，实现插件、技能、多 Agent、记忆等专项功能的精细化管控。

### 1. 插件配置

- **核心路径**：`~/.openclaw/plugins/`
    
- **作用**：存放所有已安装的插件代码、依赖与专属配置，是 OpenClaw 插件化扩展能力的核心目录
    
- **关键配置文件**：
    
    - `plugins/catalog.json`：插件目录清单，记录插件源、版本、安装信息，用于插件的发现、更新与卸载
        
    - `plugins/<插件名>/plugin.json`：单插件的清单配置文件，定义插件的 ID、版本、依赖、入口文件、权限声明、可配置项，是插件加载的核心依据
        
    - 插件的运行时配置，统一在主配置 `openclaw.json` 的 `plugins.entries` 字段中管理，支持启用 / 禁用、参数配置、黑白名单控制
        

### 2. 技能配置

- **核心路径**：`~/.openclaw/skills/`（全局技能）、`workspace/skills/`（工作空间专属技能）
    
- **作用**：存放所有已安装的自定义技能，每个技能对应一个独立子文件夹，是 Agent 能力扩展的核心载体
    
- **关键配置文件**：
    
    - `skills/<技能名>/SKILL.md`：技能的核心定义文件，包含技能的触发条件、执行流程、工具调用规则、提示词模板、权限边界，系统启动时自动扫描加载
        
    - 技能的全局启用 / 禁用规则，在主配置 `openclaw.json` 的 `skills` 字段中管理
        

### 3. 多 Agent 独立配置

- **核心路径**：`~/.openclaw/agents/<Agent-ID>/`
    
- **作用**：为单个 Agent 提供独立的配置覆盖、状态存储与上下文隔离，实现单网关运行多个完全独立的智能助理
    
- **关键配置**：每个子目录下可存放专属的 `config.json` 配置文件、独立的 workspace 目录、会话历史，其配置会覆盖全局主配置的默认值，实现精细化的多 Agent 管控
    

### 4. 记忆与会话配置

- **核心路径**：`~/.openclaw/memory/`
    
- **作用**：存放 Agent 的对话历史、向量记忆库、语义索引数据，是长期记忆能力的核心存储目录
    
- **关键文件**：`memory/<会话ID>.sqlite`：单会话的 SQLite 向量记忆数据库，存储对话转录、记忆提炼、向量嵌入数据，支持语义检索与跨会话记忆调用
    

## 四、辅助 / 系统自动生成配置文件

这类文件由系统自动生成与维护，用于配置备份、安全审计、状态管理，不建议手动修改。

|   |   |
|---|---|
|文件路径|核心作用|
|`~/.openclaw/openclaw.json.bak` / `.bak.1` 等|主配置文件的自动备份文件，用于配置错误时的版本回滚，每次修改主配置时系统自动生成备份|
|`~/.openclaw/exec-approvals.json`|执行审批记录文件，记录用户已批准 / 拒绝的危险工具调用、高风险操作，用于安全审计与重复操作免审批|
|`~/.openclaw/update-check.json`|版本更新检查记录文件，存储系统版本更新的检查时间、最新版本信息，避免频繁请求更新服务|
|`~/.openclaw/gateway.log`|网关运行日志文件，记录系统启动、运行、报错的全量日志，用于问题排查与运维诊断|
