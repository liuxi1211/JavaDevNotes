
## 一、核心总览

驾驭工程是 AI 工程化的核心生产范式，核心哲学为 \_\_「人类掌舵，智能体执行（Human Steer, Agent Execute）」\_\_，行业通用公式为 **Agent = LLM + Harness**。它不直接优化大模型本身，而是通过工程化手段构建模型运行的完整管控环境，将 AI 的不可控性转化为确定性产出。

记忆层、执行层、编排层、反馈层、治理层五层架构，是当前生产级 Harness 系统的主流收敛形态，五层自内向外形成闭环，分别对应解决 AI「记不住、做不对、没章法、不会改、不安全」五大核心痛点。所有业界产品实践均是这套体系在不同场景下的落地变体。

## 二、五层体系核心设计与实践佐证

### 1. 记忆层：智能体的持久化大脑

**核心定位**：解决大模型上下文窗口有限、跨会话失忆、记忆污染的本质缺陷，是 Agent 实现长周期任务、积累经验复用的底层地基。 **核心设计机制**：

- 采用三级分层存储架构：工作内存（短期，单轮推理生命周期）、会话内存（中期，单任务生命周期）、长期记忆（永久，跨任务复用）
    
- 配套三大核心能力：精准检索召回、自动压缩提纯、多类型记忆隔离
    

**落地实践佐证**：

- **Claude Code 完整落地三级记忆体系**：短期工作内存直接复用模型上下文窗口，仅存储当前推理步骤的临时变量、中间结果与工具返回值，单轮结束后自动清理；中期会话记忆持久化在本地 `.claude` 目录，保存完整对话历史、文件修改记录、执行日志与任务进度，支持中断后断点续跑；长期记忆依托项目根目录的两类文件，`CLAUDE.md` 存放固定的项目规范、构建命令与禁止项，`MEMORY.md` 存放动态积累的经验与踩坑记录，每次启动项目自动加载。同时内置上下文自动压缩机制，对冗余对话做摘要提纯，避免窗口溢出，并严格隔离系统规则、任务状态与历史经验三类记忆，防止互相污染。
    
- OpenAI 内部项目通过 `AGENTS.md` 结构化手册沉淀长期规则，避免 AI 反复犯同类错误
    
- Stripe Minions 通过结构化任务 Spec 注入上下文，裁剪无关工具信息，从源头减少记忆污染
    

### 2. 执行层：智能体的行动执行终端

**核心定位**：AI 与真实世界交互的接口，负责将模型决策转化为实际可执行动作并返回标准化结果，是 AI 从文本生成器走向生产工具的核心标志。 **核心设计原则**：最小权限、隔离运行、错误标准化 **核心设计机制**：

- 工具标准化封装：统一入参、出参、错误格式，降低模型适配成本
    
- 安全沙箱隔离：所有动作在隔离环境运行，防止误操作与权限逃逸
    
- 执行容错兜底：内置参数校验、自动重试、错误结构化返回机制
    

**落地实践佐证**：

- **Claude Code 基于 MCP 协议构建标准化工具层**：将文件读写、终端命令、代码搜索、网页访问、第三方扩展等所有能力统一封装为标准接口，入参、出参、错误格式完全一致，模型无需适配不同工具的返回逻辑。配套完整的 Pre/Post 执行钩子：工具调用前自动做参数校验与权限拦截，调用后自动执行结果格式化、代码风格统一、规范校验等后置处理。同时对命令执行错误做结构化提取，自动归类错误类型、定位问题位置、给出修复方向，大幅提升 AI 自修复成功率；所有操作默认限定在当前项目工作目录内，严格遵循最小权限原则。
    
- Stripe 通过独立 Devbox 实例执行所有任务，环境与生产完全隔离，用完即销毁
    
- Mitchell Hashimoto 提出专用验证工具思路，让 AI 自主完成结果校验，闭环无需人工介入
    

### 3. 编排层：智能体的任务指挥官

**核心定位**：驾驭工程的中枢神经，解决 AI 长任务跳脱、规划混乱、半途而废的问题，决定了 Agent 处理复杂任务的能力上限。 **核心设计范式**：行业已普遍放弃纯 LLM 自主编排的「随机游走」路线，全面转向**混合编排范式**—— 确定性流程做骨架，LLM 仅负责需要推理的节点，在可控性与灵活性之间寻找平衡。 **核心设计机制**：

- 标准执行闭环：Plan-Act-Observe-Reflect（规划 - 执行 - 观察 - 反思）循环
    
- 任务全生命周期管控：拆解、调度、断点续跑、异常终止、完成度校验
    
- 多智能体调度：支持主从分工、角色化协作、并行任务处理
    

**落地实践佐证**：

- **Claude Code 采用分层递进式混合编排架构**，随任务复杂度自动提升约束强度：基础层为 QueryEngine ReAct 原子循环，由模型自主决策工具调用，灵活度最高；中型任务自动启用 Plan Mode，强制先生成分步执行计划与每步验收标准，用户可审批调整；长周期任务通过 Task System 拆分为多个独立子任务，追踪每个任务的状态并支持断点续跑；复杂并行场景可调用 Subagent 工具，派生子 Agent 在隔离上下文中并行执行后汇总结果；团队级项目支持 Coordinator Mode，由调度 Agent 统筹多角色分工，自身不直接操作文件。内置完成度拦截钩子，当模型判定任务完成时，系统会在干净上下文中独立对照原始目标做验收校验，杜绝 AI 提前收尾。
    
- Stripe Blueprint 采用「确定性节点 + Agent 节点」混编状态机，简单流程写死、复杂推理交模型，兼顾稳定性与灵活性
    
- Kiro 采用 Spec 驱动的强确定性编排，将需求 - 设计 - 开发全流程固化，极致保障产出可控
    

### 4. 反馈层：智能体的持续进化引擎

**核心定位**：驾驭工程的灵魂与核心价值层，实现「一次犯错，永久修正」的正向飞轮。其核心不是评价 AI 输出好坏，而是将问题转化为永久性的系统能力。 **核心设计机制**：

- 双轨结果评估：自动化规则校验 + 人在回路审核
    
- 错误归因分类：区分知识缺失、规划错误、工具误用等不同原因，对应不同优化路径
    
- 结构化知识沉淀：将验证有效的经验、规则、方案写入长期记忆，实现跨任务复用
    

**落地实践佐证**：

- **Claude Code 构建了「执行 - 校验 - 修复 - 沉淀」的闭环反馈机制**：单步工具执行失败时，自动基于结构化错误信息进行自修复重试，无需人工干预；任务完成后自动对照原始目标做完整性校验，发现遗漏自动补全。同时支持经验自动沉淀：每次任务中的有效解决方案、踩坑记录与用户修正意见，会自动摘要后追加到项目 `MEMORY.md` 中，下次遇到同类场景自动召回，真正实现「一次修正，永久生效」的正向飞轮。
    
- Mitchell Hashimoto 的 `AGENTS.md` 规则全部源自真实 AI 错误，新增规则后同类错误复发率接近为 0
    
- OpenAI 通过自修复、AI 互审、清洁 Agent 三层闭环，实现日常质量优化无需人工介入
    
- Stripe 采用失败升级机制，AI 无法修复的问题人工处理后，反向沉淀为系统自动化能力
    

### 5. 治理层：智能体的安全合规护栏

**核心定位**：贯穿全流程的管控体系，定义 Agent「不能做什么」，是 AI 能力从试验环境进入生产环境的前置门槛。 **核心设计原则**：权限最小化、全链路可审计、异常可熔断 **核心设计机制**：

- 分级权限管控：采用「自动放行 - 人工审批 - 直接拦截」三级机制，匹配不同操作风险等级
    
- 全链路安全防护：内容护栏、环境隔离、资源熔断多重保障
    
- 合规审计留痕：所有模型调用、工具执行、人工操作全程可追溯
    

**落地实践佐证**：

- **Claude Code 以 PreToolUse 前置钩子为核心构建全链路治理体系**，支持「自动放行 - 人工确认 - 直接拦截」三级权限规则：低风险的文件读取、信息检索类操作自动放行；高风险的文件写入、系统命令、网络请求可配置人工确认；高危删除命令、敏感文件访问直接拦截，根本不进入模型推理流程。遵循本地优先原则，所有数据默认存储在用户本地，支持配置敏感文件黑名单从源头隔离数据风险；全链路操作留痕，所有对话、工具调用、文件修改均有完整日志，支持全程回溯与合规审计。
    
- Stripe 通过环境物理隔离 + 操作分级授权，实现每周千级 PR 的无人值守安全运行
    
- OpenAI 将架构规范、安全要求下沉为 Linter 强制校验规则，比提示词约束更可靠
    

## 三、五层协同运行机制

五层并非孤立堆叠，而是形成双层联动的完整体系：

1. **单次任务执行闭环**：治理层先做输入合规校验 → 编排层调取记忆层知识生成计划 → 调度执行层分步执行 → 反馈层逐次评估结果 → 完成后沉淀经验至记忆层
    
2. **长期能力进化飞轮**：每完成一次任务，有效经验都会永久沉淀到系统中，后续同类任务的规划更优、错误更少、通过率更高，Agent 可靠性随使用持续提升
    
3. **治理层全链路穿透**：治理逻辑并非仅存在于最外层，而是嵌入记忆准入、计划合规、操作授权、审计留痕等每一层的关键节点，实现全流程可控
    

## 四、落地路径与核心认知

### 分阶段落地优先级

生产级 Harness 体系无需一次性搭全五层，业界通用落地节奏为：

1. **基础可用阶段**：优先落地执行层 + 治理层底线能力，解决「能跑起来、不出事」的问题
    
2. **复杂任务阶段**：完善编排层 + 记忆层，支持长任务拆解与跨会话记忆，解决「能处理复杂任务、不失忆」的问题
    
3. **持续进化阶段**：建设反馈层体系，搭建自动化评估与经验沉淀机制，实现「越用越靠谱」的正向飞轮
    

### 核心认知澄清

- 驾驭工程 ≠ 提示词工程：提示词优化是单次输入技巧，驾驭工程是整套运行环境的系统工程
    
- 驾驭工程 ≠ Agent 框架：LangChain、LangGraph 等是实现工具，驾驭工程是架构方法论与设计思想，不绑定具体技术栈
    
- 治理约束不是限制能力：边界约束的目的是让 AI 在安全范围内充分发挥价值，而非削弱其能力
