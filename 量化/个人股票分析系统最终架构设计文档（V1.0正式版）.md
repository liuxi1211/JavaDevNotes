**架构原则**：Java 做稳定服务底座，Python 做纯计算引擎，前端纯数据驱动渲染
**设计目标**：长期运行稳定、开发效率高、可扩展性强、完全解耦
**技术栈**：Spring Boot 3\.x \+ Python 3\.11\+ \+ Streamlit \+ SQLite

### 2\. 架构核心原则

1. **单一职责原则**：每个层只做自己最擅长的事

2. **完全解耦原则**：层与层之间只通过 REST API 通信，无任何直接依赖

3. **无状态原则**：Python 计算层完全无状态，可随时重启和扩展

4. **统一入口原则**：所有前端请求只走 Java 服务，Java 作为唯一 API 网关

5. **渐进式开发原则**：先实现 MVP，再逐步完善功能，不追求一步到位

### 4\. 核心能力说明

- **Python 客户端代理**：封装所有对 Python 服务的调用，统一处理超时、重试、熔断和异常转换

- **统一异常处理**：全局异常拦截器，将所有异常转换为统一格式的 JSON 响应

- **统一响应格式**：所有接口返回`\{code: 200, message: \&\#34;success\&\#34;, data: \{\}\}`格式

- **参数校验**：使用 Jakarta Validation 实现注解式参数校验

- **任务持久化**：Quartz 任务信息持久化到数据库，重启不丢失

- **本地缓存**：使用 Caffeine 缓存热点数据，减少数据库和 Python 服务调用

## 五、数据存储层详细设计

### 1\. 数据库选型

- **初期（0\-2 年）**：SQLite 3\.x

    - 优点：零配置、文件型数据库、无需安装、备份简单

    - 缺点：并发写入性能有限（个人使用完全足够）

- **后期（2 年以上）**：PostgreSQL 16\.x

    - 优点：功能强大、性能优秀、支持复杂查询和并发访问

    - 缺点：需要安装和配置

### 2\. 核心数据表设计（固定不变）


## 六、通信协议设计

### 1\. 统一响应格式（所有接口必须遵守）

```json
{
  "code": 200,          // 状态码：200成功，其他失败
  "message": "success", // 消息
  "data": {}            // 数据主体
}
```

### 2\. 核心接口定义

#### Java 端提供给前端的接口（前端唯一调用入口）

|接口地址|请求方法|功能说明|
|---|---|---|
|/api/stock/list|GET|获取股票基本信息列表|
|/api/stock/daily|GET|获取股票日线数据|
|/api/strategy/list|GET|获取策略列表|
|/api/strategy/save|POST|保存策略配置|
|/api/backtest/run|POST|运行策略回测|
|/api/backtest/history|GET|获取回测历史记录|
|/api/position/list|GET|获取持仓列表|
|/api/position/save|POST|保存持仓信息|

#### Java 端调用 Python 端的接口

|接口地址|请求方法|功能说明|
|---|---|---|
|/api/python/data/fetch|POST|获取指定股票的历史数据|
|/api/python/data/fetch\-all|POST|获取所有股票的最新数据|
|/api/python/backtest/run|POST|执行策略回测|
|/api/python/indicator/calculate|POST|计算技术指标|
|/api/python/factor/analyze|POST|进行因子分析|

### 3\. 通信保障机制

- **超时设置**：数据获取接口 30 秒，回测接口 5 分钟

- **重试机制**：失败请求指数退避重试（最多 3 次，间隔 1s/2s/4s）

- **熔断机制**：连续 5 次失败触发熔断，熔断时间 30 秒

- **健康检查**：Java 端每分钟检查 Python 服务健康状态

- **日志记录**：所有接口调用记录请求参数、响应结果和耗时
