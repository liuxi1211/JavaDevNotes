# 个人股票分析软件架构方案

## 一、方案概述

针对个人投资者科学炒股的需求，设计一套轻量、高效、易部署的本地化股票分析系统。系统采用**Java\+Python 混合架构**，充分发挥两种语言的优势：

- Java 负责业务逻辑、用户交互、任务调度与系统集成，提供稳定的服务支撑

- Python 负责金融数据获取与高性能量化计算，利用成熟的生态快速实现量化能力

整个系统采用本地化部署，无需依赖复杂的云服务，满足个人用户隐私、离线使用的需求，同时兼顾开发效率与运行性能。

## 二、整体架构设计

### 2\.1 架构分层

系统采用四层分层架构，职责清晰，低耦合高内聚：

```Plain Text
┌─────────────────────────────────────────────────────────┐
│ 前端交互层 (Frontend)                                    │
│ Thymeleaf + Bootstrap5 + ECharts 内嵌于SpringBoot        │
└───────────────────────────┬─────────────────────────────┘
                            │ HTTP/JSON
┌───────────────────────────▼─────────────────────────────┐
│ 业务服务层 (Java Backend)                                │
│ SpringBoot + Caffeine + Quartz + SQLite Client          │
└───────────────────────────┬─────────────────────────────┘
                            │ HTTP/JSON
┌───────────────────────────▼─────────────────────────────┐
│ 计算服务层 (Python Engine)                               │
│ FastAPI + AKShare + AKQuant + Pandas                    │
└───────────────────────────┬─────────────────────────────┘
                            │ 本地文件访问
┌───────────────────────────▼─────────────────────────────┐
│ 数据存储层 (Storage)                                     │
│ SQLite 3 (WAL模式) 统一数据存储                          │
└─────────────────────────────────────────────────────────┘
```

### 2\.2 核心优势

1. **轻量无依赖**：所有服务本地部署，无需安装 MySQL、Redis 等重型中间件，一键启动即可使用

2. **性能均衡**：Python 的量化生态 \+ Rust 加速的 AKQuant 引擎，保证计算性能；Java 的成熟框架保证服务稳定性

3. **数据统一**：SQLite 统一存储所有数据，双服务共享数据，避免数据同步问题

4. **离线可用**：所有静态资源本地存储，数据下载完成后可离线分析历史数据

## 四、核心模块设计

### 4\.1 Python 计算服务模块

Python 服务专注于数据获取与量化计算，对外提供 REST API 供 Java 服务调用，核心模块如下：

#### 4\.1\.1 数据采集模块

- **行情数据采集**：通过 AKShare 获取 A 股日线、分钟线、实时行情数据

    - 全市场日线数据采集：单线程仅需 15 分钟即可完成全量更新

    - 实时行情：支持盘中 15 分钟延时行情获取，满足盯盘需求

- **基本面数据采集**：财务报表、估值指标 \(PE/PB/ROE\)、分红拆股数据

- **资金流数据采集**：北向资金、龙虎榜、主力资金流向数据

- **数据清洗**：处理停牌数据、缺失值、异常值，标准化数据格式

#### 4\.1\.2 量化计算模块

基于 AKQuant 的 Rust 高性能引擎，提供：

- **技术指标计算**：MACD、KDJ、RSI、BOLL、EMA 等常用技术指标

- **策略回测引擎**：支持自定义策略回测，模拟真实交易环境

    - 输出回测报告：年化收益、最大回撤、夏普比率等核心指标

- **因子计算**：基本面因子、技术因子，支持多因子选股

### 4\.2 Java 业务服务模块

Java 服务负责系统的业务逻辑、用户交互与任务调度，是系统的核心入口：

#### 4\.2\.1 远程调用模块

#### 4\.2\.2 缓存模块

基于 Caffeine 实现本地缓存，优化热点数据访问：

- 缓存范围：大盘指数行情、自选股行情、常用股票基础信息

- 过期策略：

    - 盘中实时数据：15 分钟过期（匹配行情延时）

    - 收盘后日线数据：次日开盘前过期（收盘后数据不再变化）

- 缓存淘汰：LRU 策略，最多缓存 1000 个热点数据，避免内存溢出

#### 4\.2\.3 定时任务模块

基于 Quartz 实现自动化任务，解放手动操作：

## 五、数据存储设计

### 5\.1 SQLite 优化配置

针对多进程访问场景，启用 SQLite 的 WAL 模式，解决并发读写问题：

```sql
-- 初始化数据库时执行，开启WAL模式
PRAGMA journal_mode = WAL;
-- 同步模式调整，提升写入性能
PRAGMA synchronous = NORMAL;
-- 缓存大小设置，提升查询性能
PRAGMA cache_size = -20000; -- 20MB缓存
```

> 开启 WAL 模式后，SQLite 支持**1 写多读**并发，完美匹配我们的场景：Python 服务负责写入，Java 服务负责读取，读写互不阻塞，完全满足个人用户的并发需求。

## 八、关键特性与优化

### 8\.1 增量数据更新

数据更新采用增量更新，只更新缺失的日期数据，避免全量重拉，提升更新速度：

- 首次运行：全量拉取历史数据（可配置拉取最近 3 年 / 5 年数据）

- 日常更新：只拉取最后一个交易日之后的数据，1 分钟内即可完成更新

### 8\.2 失败重试机制

- 网络调用失败自动重试，最多重试 3 次，间隔 1 秒

- 数据拉取失败后，下次定时任务自动重试，保证数据完整性

- 服务启动失败自动重启，保证系统稳定性

### 8\.3 数据备份

自动定时备份 SQLite 数据库文件，保留最近 7 天的备份，防止数据损坏或误操作。

### 8\.4 离线可用

所有数据下载到本地后，无需网络即可查看历史行情、进行回测分析，满足离线使用需求。
