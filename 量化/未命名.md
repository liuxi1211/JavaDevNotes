## 1. 产品定位与设计哲学

### 1.1 核心认知

做了 10 年 A 股，最深刻的体会是：**散户亏钱不是因为不懂技术，而是因为没有纪律**。

量化系统的本质不是发明一套神奇的赚钱公式，而是：

1. **把你的经验变成可执行的规则** — 你知道"均线多头排列买入"是对的，但你做不到每次都严格执行
    
2. **用历史数据验证你的判断** — 你觉得某个策略有效，但你需要数字证明它过去 5 年到底赚了多少
    
3. **让机器替你盯盘** — 5000 只股票人眼看不过来，机器可以每天扫描全部
    
4. **控制风险保住本金** — 活着比赚钱重要，单票重仓、追涨杀跌这些毛病系统帮你拦住
    

### 1.2 设计哲学

|原则|说明|
|---|---|
|**策略即代码**|策略用 Python 脚本编写，不是可视化拖拽。写代码比拖控件灵活 100 倍，个人项目不需要低代码|
|**引擎即插件**|akquant 作为回测引擎以插件形式接入，未来可以无缝替换为 backtrader、vnpy 等其他引擎|
|**数据即服务**|Java 端作为数据中台，Python 端通过标准接口获取数据，解耦数据与计算|
|**配置优于硬编码**|策略参数、风控规则、信号推送渠道全部可配置，改配置不改代码|
|**简单策略优先**|先跑通简单的均线策略，再逐步迭代复杂策略。不要一上来就搞多因子模型|

### 1.3 产品边界

**做什么**：

- 日线级别的中低频策略研究、回测、信号生成
    
- 个人持仓管理和风控
    
- 策略绩效追踪和复盘
    

**不做什么**：

- 不做高频交易 / 秒级策略
    
- 不做自动下单（MVP 阶段）
    
- 不做多人协作 / 社区功能
    
- 不做实时行情推送（用收盘后信号替代）

### 3.1 因子库 (Factor Library)

#### 3.1.1 设计目标

因子是策略的积木。好的因子库设计决定了你能多快地组合出新的策略。

#### 3.1.2 因子分类体系

因子库  
├── 技术面因子 (Technical)        — 量价关系，择时用  
│   ├── 趋势类: MA, MACD, DMI, SAR  
│   ├── 动量类: RSI, KDJ, WR, CCI  
│   ├── 波动类: BOLL, ATR, KELCH  
│   └── 量能类: OBV, VOL_MA, AMOUNT_RANK  
│  
├── 基本面因子 (Fundamental)      — 公司质量，选股用  
│   ├── 估值类: PE_TTM, PB, PS_TTM, EV/EBITDA  
│   ├── 质量类: ROE, ROA, 净利润率, 毛利率  
│   ├── 成长类: 净利润增速, 营收增速, EPS增速  
│   └── 安全类: 资产负债率, 流动比率, 经营现金流/净利润  
│  
├── 情绪面因子 (Sentiment)        — 市场资金行为，过滤用  
│   ├── 换手率, 量比  
│   ├── 北向资金净买入, 北向资金持股占比变化  
│   ├── 龙虎榜上榜次数, 上榜买入额  
│   └── 融资融券余额变化  
│  
└── 统计面因子 (Statistical)      — 高阶计算  
    ├── 波动率 (历史/隐含)  
    ├── 偏度/峰度  
    ├── 相关性矩阵  
    └── 因子 IC/IR 值

#### 3.2.2 策略脚本的规范

每个策略脚本必须实现标准接口，确保引擎可以统一调度：

from akquant import Strategy  
  
class SMACrossStrategy(Strategy):  
    """  
    双均线交叉策略  
  
    入场：短期均线上穿长期均线（金叉）  
    出场：短期均线下穿长期均线（死叉）或触发止损  
    """  
  
    # ===== 策略元信息（与数据库注册信息一致）=====  
    META = {  
        "name": "sma_cross",  
        "display_name": "双均线交叉",  
        "category": "TREND",  
        "params_schema": { ... },    # 与数据库 params_schema 一致  
        "params_default": {"sma_short": 5, "sma_long": 20, "stop_loss_pct": 0.05},  
    }  
  
    def __init__(self, params: dict):  
        super().__init__()  
        self.params = params  
        self.sma_short = params.get("sma_short", 5)  
        self.sma_long = params.get("sma_long", 20)  
        self.stop_loss_pct = params.get("stop_loss_pct", 0.05)  
        self.ma_short_history = []  
        self.ma_long_history = []  
        self.entry_price = None  
  
    def on_bar(self, bar):  
        # 更新均线  
        self.ma_short_history.append(bar.close)  
        self.ma_long_history.append(bar.close)  
  
        if len(self.ma_short_history) < self.sma_long:  
            return  # 数据不足，不操作  
  
        ma_s = sum(self.ma_short_history[-self.sma_short:]) / self.sma_short  
        ma_l = sum(self.ma_long_history[-self.sma_long:]) / self.sma_long  
  
        prev_ma_s = sum(self.ma_short_history[-self.sma_short-1:-1]) / self.sma_short  
        prev_ma_l = sum(self.ma_long_history[-self.sma_long-1:-1]) / self.sma_long  
  
        pos = self.get_position(bar.symbol)  
  
        # 金叉买入  
        if pos == 0 and prev_ma_s <= prev_ma_l and ma_s > ma_l:  
            self.buy(symbol=bar.symbol, quantity=100)  
            self.entry_price = bar.close  
  
        # 死叉 或 止损 卖出  
        elif pos > 0:  
            should_sell = False  
            reason = ""  
  
            if prev_ma_s >= prev_ma_l and ma_s < ma_l:  
                should_sell = True  
                reason = "dead_cross"  
  
            if self.entry_price and bar.close <= self.entry_price * (1 - self.stop_loss_pct):  
                should_sell = True  
                reason = "stop_loss"  
  
            if should_sell:  
                self.close_position(symbol=bar.symbol)  
                self.entry_price = None

#### 3.2.3 策略生命周期

  DRAFT ─────→ ACTIVE ─────→ PAUSED ─────→ ACTIVE  
  (编写中)      (运行中)      (暂停)         (恢复)  
                  │  
                  └─────→ ARCHIVED  
                          (归档，不再运行但保留历史)

- **DRAFT**：策略脚本已创建，参数已配置，但尚未进行回测验证
    
- **ACTIVE**：策略已通过回测验证，纳入每日信号生成
    
- **PAUSED**：临时暂停，不参与信号生成，保留所有历史数据
    
- **ARCHIVED**：策略下线，保留回测历史和信号记录供复盘
    

#### 3.2.4 策略版本管理

每次修改策略脚本或参数后，系统自动记录变更：

CREATE TABLE quant_strategy_version (  
    id              INTEGER PRIMARY KEY AUTOINCREMENT,  
    strategy_id     INTEGER NOT NULL,  
    version         INTEGER NOT NULL,             -- 自增版本号  
    script_content  TEXT NOT NULL,                -- 脚本快照（存一份当前脚本内容）  
    params          TEXT NOT NULL,                -- JSON: 本次使用的参数  
    change_note     TEXT,                         -- 变更说明  
    created_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP,  
    UNIQUE(strategy_id, version),  
    FOREIGN KEY (strategy_id) REFERENCES quant_strategy(id)  
);

### 3.3 回测中心 (Backtesting)

#### 3.3.1 设计原则

回测是量化系统最核心的功能，也是你验证策略想法的唯一手段。设计上必须做到：

- **快速验证**：一个想法 → 配好参数 → 点击回测 → 5 分钟内看到结果
    
- **结果可信**：严格模拟 A 股真实交易规则，避免回测结果虚高
    
- **对比分析**：支持策略之间横向对比，支持与基准（沪深 300）对比
    

#### 3.3.2 回测配置

CREATE TABLE quant_backtest (  
    id              INTEGER PRIMARY KEY AUTOINCREMENT,  
    strategy_id     INTEGER NOT NULL,

### 3.6 风控系统 (Risk Management)

#### 3.6.1 设计思路

风控是系统的安全网。作为老股民，我知道最容易犯的错误就那几个：单票重仓、不止损、逆势加仓。风控规则不需要多复杂，关键是**严格执行**。

风控分为两层：

- **策略级风控**：每个策略自己的止损止盈规则（写在策略脚本里）
    
- **账户级风控**：全局风控规则，覆盖所有策略（Java 端执行）
    

#### 3.6.2 风控规则配置

CREATE TABLE quant_risk_rule (  
    id              INTEGER PRIMARY KEY AUTOINCREMENT,  
    name            TEXT NOT NULL UNIQUE,           -- 规则英文标识  
    display_name    TEXT NOT NULL,                  -- 规则中文名  
    category        TEXT NOT NULL,                  -- POSITION / LOSS / TRADE / LIQUIDITY  
    description     TEXT,  
    rule_config     TEXT NOT NULL,                  -- JSON: 规则参数  
    severity        TEXT NOT NULL DEFAULT 'WARN',   -- WARN(警告) / BLOCK(拦截)  
    enabled         INTEGER DEFAULT 1,  
    priority        INTEGER DEFAULT 0,              -- 优先级，数值越大越先执行  
    created_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP  
);

**内置风控规则**：

|规则|类别|默认参数|说明|
|---|---|---|---|
|`MAX_SINGLE_POSITION`|POSITION|`{"max_pct": 0.08}`|单票仓位不超过 8%|
|`MAX_TOTAL_POSITION`|POSITION|`{"max_pct": 0.90}`|总仓位不超过 90%|
|`MAX_INDUSTRY_CONCENTRATION`|POSITION|`{"max_pct": 0.25}`|同一行业仓位不超过 25%|
|`DAILY_LOSS_LIMIT`|LOSS|`{"max_pct": 0.01}`|单日亏损超过 1% 停止开新仓|
|`MAX_DRAWDOWN_CIRCUIT_BREAKER`|LOSS|`{"max_pct": 0.08}`|最大回撤超 8% 触发降仓|
|`STOP_LOSS_CHECK`|LOSS|`{"default_pct": 0.05}`|持仓浮亏超 5% 自动提醒卖出|
|`T_PLUS_1_CHECK`|TRADE|`{}`|当日买入不可当日卖出|
|`LIMIT_PRICE_CHECK`|TRADE|`{}`|涨跌停标的不建议交易|
|`MIN_LIQUIDITY`|LIQUIDITY|`{"min_amount": 50000000}`|日均成交额低于 5000 万不交易|

#### 3.6.3 风控执行流程

信号产生 → 信号进入风控检查队列  
    │  
    ├─→ 遍历所有 enabled 的风控规则（按 priority 排序）  
    │     │  
    │     ├─→ BLOCK 规则触发 → 信号标记为"风控拦截"，记录拦截原因  
    │     │     例："单票仓位已达 8%，不可继续加仓贵州茅台"  
    │     │  
    │     └─→ WARN 规则触发 → 信号保留，但附加警告信息  
    │           例："当前总仓位 85%，接近上限 90%"  
    │  
    └─→ 风控通过的信号 → 推送到信号中心

### 3.7 引擎适配层 (Engine Adapter)

#### 3.7.1 设计目标

这是扩展性设计的核心。你今天选择 akquant，但未来可能想换 backtrader、vnpy，或者自己写引擎。引擎适配层确保切换引擎不需要改业务逻辑。

#### 3.7.2 适配器接口

Python 端定义引擎抽象接口：

from abc import ABC, abstractmethod  
from typing import Any  
from dataclasses import dataclass  
  
@dataclass  
class BacktestResult:  
    """回测结果的标准输出，所有引擎适配器必须返回这个格式"""  
    total_return_pct: float  
    annualized_return: float  
    max_drawdown_pct: float  
    sharpe_ratio: float  
    sortino_ratio: float  
    calmar_ratio: float  
    win_rate: float  
    profit_factor: float  
    total_trades: int  
    avg_trade_return_pct: float  
    volatility: float  
    excess_return_pct: float | None = None  
    var_95: float | None = None  
    cvar_95: float | None = None  
    equity_curve: list[dict] | None = None    # [{date, equity}]  
    trades: list[dict] | None = None           # [{date, symbol, type, price, qty, pnl}]  
    report_html_path: str | None = None  
  
@dataclass  
class SignalResult:  
    """信号生成的标准输出"""  
    signals: list[dict]  # [{stock_code, signal_type, strength, price, reason}]  
  
  
class EngineAdapter(ABC):  
    """回测引擎适配器抽象基类"""  
  
    @abstractmethod  
    def run_backtest(  
        self,  
        strategy_class,  
        data: Any,  
        params: dict,  
        config: dict,  
    ) -> BacktestResult:  
        """执行回测"""  
        ...  
  
    @abstractmethod  
    def run_signal(  
        self,  
        strategy_class,  
        data: Any,  
        params: dict,  
        signal_date: str,  
    ) -> SignalResult:  
        """生成信号"""  
        ...  
  
    @abstractmethod  
    def run_grid_search(  
        self,  
        strategy_class,  
        data: Any,  
        param_grid: dict,  
        config: dict,  
        metric: str,  
        n_jobs: int,  
    ) -> list[dict]:  
        """参数优化"""  
        ...  
  
  
class AKQuantAdapter(EngineAdapter):  
    """akquant 引擎适配器"""  
  
    def run_backtest(self, strategy_class, data, params, config):  
        import akquant as aq  
        result = aq.run_backtest(  
            data=data,  
            strategy=strategy_class,  
            initial_cash=config.get("initial_cash", 100000),  
            symbols=config.get("symbols"),  
            commission_rate=config.get("commission_rate", 0.00025),  
            # ... 映射 config 到 akquant 参数  
        )  
        # 转换为标准 BacktestResult  
        return self._convert_result(result)  
  
    # ... 其他方法实现  
  
  
class BacktraderAdapter(EngineAdapter):  
    """未来可选：backtrader 引擎适配器"""

### 3.8 数据导出服务 (Data Export)

#### 3.8.1 设计目标

Python 端需要从 SQLite 读取数据来喂给 akquant。这个模块负责把 SQLite 数据转为 akquant 能吃的 DataFrame 格式。

#### 3.8.2 标准数据格式

akquant 接受的 DataFrame 格式（与 akshare 对齐）：

# 标准列名  
required_columns = ["date", "open", "high", "low", "close", "volume", "amount"]  
# 可选列  
optional_columns = ["symbol", "pre_close", "change", "pct_chg", "turnover", "adj_factor"]

#### 3.8.3 数据读取接口

class DataReader:  
    """从 SQLite 读取数据并转为标准 DataFrame"""  
  
    def __init__(self, db_path: str):  
        self.db_path = db_path  
  
    def get_daily(  
        self,  
        stock_code: str,  
        start_date: str | None = None,  
        end_date: str | None = None,  
        adjusted: bool = True,  
    ) -> pd.DataFrame:  
        """  
        获取个股日线数据  
  
        Args:  
            stock_code: ts_code 格式，如 "000001.SZ"  
            start_date: 起始日期，如 "2020-01-01"  
            end_date: 结束日期，如 "2026-05-25"

### 3.9 内置策略模板

提供 5 个经过 A 股市场验证的经典策略，作为学习和修改的起点：

#### 3.9.1 双均线交叉 (sma_cross)

|项目|说明|
|---|---|
|适用场景|趋势跟踪，适合 ETF 和龙头股|
|买入条件|短期均线上穿长期均线（金叉）|
|卖出条件|短期均线下穿长期均线（死叉）或触发止损|
|默认参数|`sma_short=5, sma_long=20, stop_loss_pct=0.05`|
|A 股注意|震荡市均线频繁金叉死叉，配合趋势过滤（如 MACD 方向）效果更好|

#### 3.9.2 MACD 趋势突破 (macd_breakout)

|项目|说明|
|---|---|
|适用场景|中短线波段交易|
|买入条件|MACD 金叉 + 成交量放大 1.5 倍 + 股价站上 20 日均线|
|卖出条件|MACD 死叉 或 跌破 20 日均线 或 盈利 10%|
|默认参数|`macd_fast=12, macd_slow=26, macd_signal=9, vol_ratio=1.5, profit_target=0.10`|

#### 3.9.3 低估值价值策略 (value_pick)

|项目|说明|
|---|---|
|适用场景|中长期价值投资，适合消费、医药、银行|
|选股条件|PE_TTM < 行业中位数 且 ROE > 15% 且 营收增速 > 0|
|调仓频率|月度调仓，持有前 20 只最低估的标的|
|默认参数|`max_pe=30, min_roe=0.15, min_revenue_growth=0, top_n=20, rebalance_freq=MONTHLY`|

#### 3.9.4 小市值动量策略 (small_cap_momentum)

|项目|说明|
|---|---|
|适用场景|A 股特色小市值效应，高波动高收益|
|选股条件|流通市值 50-300 亿 + 非 ST + 近 20 日涨幅 > 5% + 换手率 > 2%|
|调仓频率|周度调仓，持有前 10 只动量最强的标的|
|默认参数|`min_market_cap=50e8, max_market_cap=300e8, momentum_days=20, min_return=0.05, top_n=10`|

#### 3.9.5 北向资金跟随策略 (northbound_follow)

|项目|说明|
|---|---|
|适用场景|跟随外资动向的保守策略|
|买入条件|北向资金连续 3 日净流入 + 个股被北向加仓|
|卖出条件|北向资金连续 2 日减仓|
|默认参数|`consecutive_days=3, min_net_inflow=0, sell_consecutive=2`|

> **注意**：策略 3、4、5 依赖基本面/情绪面数据（财务、北向资金），MVP 阶段先实现策略 1、2，后续数据接入后再实现其余策略。

|---|---|
|新增因子|写一个 `@register` 函数，放入 `factor/` 目录|

|替换回测引擎|实现 `EngineAdapter` 接口，修改配置|
|新增数据源|Java 端增加数据获取逻辑，Python 端无需修改|
|新增推送渠道|实现 `NotifyChannel` 接口，注册到通知服务|

## 9. 风险与注意事项

### 9.1 投资风险

1. **回测不等于未来**：历史有效 ≠ 未来有效。策略的衰变是常态，需要持续监控
    
2. **过拟合**：参数优化最容易过拟合。防范方法：(a) 样本外验证 (b) 参数鲁棒性检查（参数微调时结果不应剧烈变化）
    
3. **幸存者偏差**：回测时使用的股票池是当前存续的股票，已经剔除了退市的。实际收益会被高估
    
4. **流动性风险**：小市值策略回测收益可能很好，但实盘时冲击成本很高
    

### 9.2 技术风险

1. **akquant 版本稳定性**：akquant 是较新的项目，API 可能变动。建议锁定版本
    
2. **SQLite 并发**：Java 写入时 Python 可能正在读取。SQLite 的 WAL 模式可以解决大部分问题
    
3. **Python 服务运维**：需要考虑进程守护、异常重启。建议用 systemd 或 supervisor 管理
    

### 9.3 合规提醒

- 所有数据仅用于个人研究，不得商用
    
- 不从事任何违反证券法规的活动
    
- 系统产生的信号仅供参考，投资决策由用户自行负责
