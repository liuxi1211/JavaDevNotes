## 一、召回层核心设计原则

1. **相关性优先**：召回是排序的基础，漏召回核心文档会直接导致搜索失败
    
2. **低延迟刚性**：P99 延迟控制在 100ms 以内，三路召回全部并行执行
    
3. **覆盖度与多样性平衡**：既要覆盖核心相关文档，也要避免结果过于单一
    
4. **业务强适配**：针对元器件型号、参数、特殊字符、权限等特殊需求优化
    
5. **可扩展性**：方便新增召回源和调整权重策略
    

## 二、核心架构：三路并行召回体系

### 2.1 架构总览

```Plain
用户输入Query → QP全链路处理 → 三路并行召回 → 结果去重 → 得分归一化 → 加权融合 → Top1000进粗排
                          ↓
        ┌─────────────┬─────────────┬─────────────┐
    实体结构化召回  核心文本召回  向量语义召回
    (精准匹配)      (泛化兜底)      (语义补全)
    优先级最高      优先级次之      优先级最低
```

### 2.2 各链路定位与边界

|         |              |                        |        |      |
| ------- | ------------ | ---------------------- | ------ | ---- |
| 召回链路    | 核心价值         | 解决的问题                  | 召回数量   | 全局权重 |
| 实体结构化召回 | 精准命中用户强确定性需求 | 型号、品牌、封装、参数的零歧义匹配      | Top200 | 3.0  |
| 核心文本召回  | 全场景泛化兜底      | NER 识别错误、模糊查询、长尾 Query | Top800 | 1.0  |
| 向量语义召回  | 语义缺口补全       | 同义词、简称、自然语言查询、替代料匹配    | Top300 | 0.5  |

## 三、各链路详细设计与 DSL 实现

### 3.1 前置约定

#### 3.1.1 索引与字段说明

- 索引名：`electronic_components`
    
- 文本字段：`title`(主匹配)、`spec_desc`(参数详情)、`brand_name`、`model_full`、`packaging_text`
    
- 结构化字段：`brand.keyword`、`model.keyword`、`packaging.keyword`、`params`(nested 参数)
    
- 向量字段：`item_vector_768`(768 维商品语义向量)
    

#### 3.1.2 QP 输出变量

- `raw_query`：用户原始输入
    
- `std_query`：QP 纠错 + 归一化主干词
    
- `core_terms`：核心刚需词数组 (型号 / 阻值 / 容值 / 主规格)
    
- `syn_terms`：同义词 + 别名数组
    
- `hyper_terms`：上下位词数组
    
- `brand_alias`：品牌别名扩展
    
- `pack_rewrite`：封装改写标准词
    
- `exact_model`：精准识别的完整型号
    
- `exact_brand`：精准识别的品牌
    
- `exact_pack`：精准识别的封装
    
- `extracted_params`：提取的结构化参数列表
    

### 3.2 第一路：实体结构化召回 DSL

**设计逻辑**：

1. 仅匹配结构化 keyword 字段，不涉及文本模糊匹配
    
2. 权重分级：完整型号 > 参数 > 品牌 > 封装
    
3. Nested 参数精准绑定，防止交叉错配
    
4. 整路全局高权重，保证精准结果优先
    

```json
{
  "size": 200,
  "search_type": "dfs_query_then_fetch",
  "_source": false,
  "query": {
    "bool": {
      "boost": 8.0,
      "should": [
        // 1. 完整型号精准命中(最高权重)
        {
          "term": {
            "model.keyword": {
              "value": "${exact_model}",
              "boost": 10.0
            }
          }
        },
        // 2. 品牌精准命中
        {
          "term": {
            "brand.keyword": {
              "value": "${exact_brand}",
              "boost": 6.0
            }
          }
        },
        // 3. 封装规格精准命中
        {
          "term": {
            "packaging.keyword": {
              "value": "${exact_pack}",
              "boost": 4.0
            }
          }
        },
        // 4. Nested结构化参数精准匹配(动态循环拼接)
        #foreach($param in ${extracted_params})
        {
          "nested": {
            "path": "params",
            "query": {
              "bool": {
                "must": [
                  {"term": {"params.name": "${param.name}"}},
                  {"term": {"params.value": "${param.value}"}}
                ]
              }
            },
            "boost": 7.0
          }
        }
        #end
      ],
      "minimum_should_match": 1
    }
  }
}
```

### 3.3 第二路：核心文本召回 DSL

**设计逻辑**：

1. 吃满 QP 所有扩展能力，分层加权
    
2. 核心刚需词单独暴力提权
    
3. 同义词、上下位词分级加权
    
4. 原始 query 短语匹配兜底，防止 QP 改错
    

```json
{
  "size": 800,
  "search_type": "dfs_query_then_fetch",
  "_source": false,
  "query": {
    "bool": {
      "should": [
        // 1. QP标准归一化主干 - 超高基础分
        {
          "multi_match": {
            "query": "${std_query}",
            "fields": ["title^4", "model_full^3", "spec_desc^1.5", "brand_name^3"],
            "type": "best_fields",
            "boost": 3.0
          }
        },
        // 2. QP识别核心刚需Term - 暴力提权
        {
          "terms": {
            "title": ${core_terms},
            "boost": 5.0
          }
        },
        // 3. 同义词/品牌别名/型号别名 - 中等加权
        {
          "multi_match": {
            "query": "${syn_terms.join(' ')} ${brand_alias.join(' ')}",
            "fields": ["title^2", "spec_desc^1.2"],
            "boost": 2.0
          }
        },
        // 4. 上下位类目泛化 - 轻度加权扩召回
        {
          "multi_match": {
            "query": "${hyper_terms.join(' ')}",
            "fields": ["title^1.2", "spec_desc^1"],
            "boost": 1.0
          }
        },
        // 5. 封装改写标准词补强
        {
          "match": {
            "packaging_text": {
              "query": "${pack_rewrite.join(' ')}",
              "boost": 2.5
            }
          }
        },
        // 6. 原始用户输入短语精准兜底(防QP翻车)
        {
          "match_phrase": {
            "title": {
              "query": "${raw_query}",
              "slop": 2,
              "boost": 4.0
            }
          }
        }
      ],
      "minimum_should_match": 1
    }
  }
}
```

### 3.4 第三路：向量语义召回 DSL

**设计逻辑**：

1. 只补 "字面不沾边、语义一致" 的场景
    
2. 低权重，不抢主排名
    
3. 配合前两路解决简称、口语、替代料匹配
    

```json
{
  "size": 300,
  "search_type": "dfs_query_then_fetch",
  "_source": false,
  "knn": {
    "field": "item_vector_768",
    "query_vector": ${query_embedding_array},
    "k": 300,
    "num_candidates": 1000,
    "boost": 1.5
  }
}
```

## 四、召回结果融合与得分校准（核心难点解决方案）

### 4.1 核心问题与误区澄清

#### 4.1.1 不同 query 的 BM25 得分绝对没有可比性

- 原因：BM25 的 IDF (逆文档频率) 与 query 包含的 term 直接相关，不同 query 的得分量级完全不同
    
- 现象：当实体召回命中高频 term (如品牌)，而文本召回命中多个稀有 term 时，文本召回得分会天然超过实体召回
    
- 误区：直接用原始得分乘以全局权重融合，会导致排序混乱
    

#### 4.1.2 固定得分 vs 权重乘基础分

|   |   |   |   |
|---|---|---|---|
|打分方式|适用场景|优点|缺点|
|**权重乘基础分 (标准做法)**|所有相关性排序场景|保留同条件下的相关性差异，与文本得分同基准，自动适配实体重要性差异|需解决跨 query 得分不可比问题|
|**固定得分**|纯业务规则强制干预 (置顶、黑名单、库存优先)|简单直接|丢失相关性差异，多条件叠加易出现逻辑混乱，跨链路无法融合|

**结论**：所有与文本匹配质量相关的打分，全部使用 "BM25 基础分 × 权重系数"；只有业务规则干预才使用固定得分。

### 4.2 工业界标准解决方案：Min-Max 归一化 + 全局权重

#### 4.2.1 核心流程

1. 三路并行查询，分别获取每路的结果列表 (DocID + 原始得分)
    
2. 对每路结果单独做 Min-Max 归一化，将得分映射到 [0,1] 区间
    
3. 乘以每路的全局权重 (实体 3.0、文本 1.0、向量 0.5)
    
4. 去重：重复 DocID 保留最高权重路的得分
    
5. 按最终得分降序排序，取 Top1000 进粗排
    

#### 4.2.2 分片级 IDF 不稳定解决方案

在所有 DSL 中添加`"search_type": "dfs_query_then_fetch"`参数，ES 会先收集全局 IDF 再计算得分，保证同一个 query 在不同分片上的得分一致。

## 五、完整 Java 代码实现

### 5.1 数据模型类

```java
import lombok.Data;
import java.util.List;
import java.util.Map;

@Data
public class QPResult {
    private String rawQuery;
    private String stdQuery;
    private List<String> coreTerms;
    private List<String> synTerms;
    private List<String> hyperTerms;
    private List<String> brandAlias;
    private List<String> packRewrite;
    private String exactModel;
    private String exactBrand;
    private String exactPack;
    private List<Map<String, String>> extractedParams;
}

@Data
public class RecallItem {
    private String docId;
    private double rawScore;      // ES返回的原始得分
    private double normalizedScore; // 归一化后的得分
    private double finalScore;    // 最终得分
    private String source;        // "entity"/"text"/"vector"

    public RecallItem(String docId, double rawScore, String source) {
        this.docId = docId;
        this.rawScore = rawScore;
        this.source = source;
    }
}
```

### 5.2 召回服务实现类

```java
import co.elastic.clients.elasticsearch.ElasticsearchClient;
import co.elastic.clients.elasticsearch.core.SearchRequest;
import co.elastic.clients.elasticsearch.core.SearchResponse;
import co.elastic.clients.elasticsearch.core.search.Hit;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;

import java.util.*;
import java.util.concurrent.CompletableFuture;
import java.util.stream.Collectors;

@Service
public class ComponentSearchRecallService {

    @Autowired
    private ElasticsearchClient esClient;

    @Autowired
    private EmbeddingService embeddingService;

    public List<String> doRecall(String rawQuery) {
        // 1. 调用QP服务获取解析结果
        QPResult qpResult = qpService.parse(rawQuery);
        
        // 2. 生成query向量
        float[] queryEmbedding = embeddingService.generateEmbedding(qpResult.getStdQuery());

        // 3. 并行发起三路召回
        CompletableFuture<List<RecallItem>> entityFuture = 
            CompletableFuture.supplyAsync(() -> doEntityRecall(qpResult));
        CompletableFuture<List<RecallItem>> textFuture = 
            CompletableFuture.supplyAsync(() -> doTextRecall(qpResult));
        CompletableFuture<List<RecallItem>> vectorFuture = 
            CompletableFuture.supplyAsync(() -> doVectorRecall(queryEmbedding));

        CompletableFuture.allOf(entityFuture, textFuture, vectorFuture).join();

        try {
            List<RecallItem> entityItems = entityFuture.get();
            List<RecallItem> textItems = textFuture.get();
            List<RecallItem> vectorItems = vectorFuture.get();

            // 4. 分别对每路做Min-Max归一化
            normalizeScores(entityItems);
            normalizeScores(textItems);
            normalizeScores(vectorItems);

            // 5. 加权融合与去重
            Map<String, RecallItem> mergedMap = new HashMap<>();
            
            // 实体召回(最高优先级)
            for (RecallItem item : entityItems) {
                item.setFinalScore(item.getNormalizedScore() * 3.0);
                mergedMap.put(item.getDocId(), item);
            }
            
            // 文本召回(中等优先级)
            for (RecallItem item : textItems) {
                item.setFinalScore(item.getNormalizedScore() * 1.0);
                if (!mergedMap.containsKey(item.getDocId())) {
                    mergedMap.put(item.getDocId(), item);
                }
            }
            
            // 向量召回(最低优先级)
            for (RecallItem item : vectorItems) {
                item.setFinalScore(item.getNormalizedScore() * 0.5);
                if (!mergedMap.containsKey(item.getDocId())) {
                    mergedMap.put(item.getDocId(), item);
                }
            }

            // 6. 排序截断
            return mergedMap.values().stream()
                .sorted((a, b) -> Double.compare(b.getFinalScore(), a.getFinalScore()))
                .limit(1000)
                .map(RecallItem::getDocId)
                .collect(Collectors.toList());

        } catch (Exception e) {
            // 降级逻辑：如果实体和向量都失败，返回纯文本召回
            try {
                List<RecallItem> textItems = doTextRecall(qpResult);
                return textItems.stream()
                    .map(RecallItem::getDocId)
                    .collect(Collectors.toList());
            } catch (Exception ex) {
                return Collections.emptyList();
            }
        }
    }

    // 实体召回实现
    private List<RecallItem> doEntityRecall(QPResult qpResult) {
        // 动态构建实体召回DSL(省略具体拼接逻辑)
        SearchRequest request = buildEntitySearchRequest(qpResult);
        
        try {
            SearchResponse<Map> response = esClient.search(request, Map.class);
            return response.hits().hits().stream()
                .map(hit -> new RecallItem(hit.id(), hit.score() != null ? hit.score() : 0.0, "entity"))
                .collect(Collectors.toList());
        } catch (Exception e) {
            return Collections.emptyList();
        }
    }

    // 文本召回实现
    private List<RecallItem> doTextRecall(QPResult qpResult) {
        // 动态构建文本召回DSL(省略具体拼接逻辑)
        SearchRequest request = buildTextSearchRequest(qpResult);
        
        try {
            SearchResponse<Map> response = esClient.search(request, Map.class);
            return response.hits().hits().stream()
                .map(hit -> new RecallItem(hit.id(), hit.score() != null ? hit.score() : 0.0, "text"))
                .collect(Collectors.toList());
        } catch (Exception e) {
            return Collections.emptyList();
        }
    }

    // 向量召回实现
    private List<RecallItem> doVectorRecall(float[] queryEmbedding) {
        // 构建向量召回DSL(省略具体拼接逻辑)
        SearchRequest request = buildVectorSearchRequest(queryEmbedding);
        
        try {
            SearchResponse<Map> response = esClient.search(request, Map.class);
            return response.hits().hits().stream()
                .map(hit -> new RecallItem(hit.id(), hit.score() != null ? hit.score() : 0.0, "vector"))
                .collect(Collectors.toList());
        } catch (Exception e) {
            return Collections.emptyList();
        }
    }

    // Min-Max归一化实现
    private void normalizeScores(List<RecallItem> items) {
        if (items.isEmpty()) {
            return;
        }
        if (items.size() == 1) {
            items.get(0).setNormalizedScore(1.0);
            return;
        }

        double minScore = Double.MAX_VALUE;
        double maxScore = Double.MIN_VALUE;
        for (RecallItem item : items) {
            double score = item.getRawScore();
            if (score < minScore) minScore = score;
            if (score > maxScore) maxScore = score;
        }

        double range = maxScore - minScore;
        if (range < 1e-6) { // 所有得分相同
            for (RecallItem item : items) {
                item.setNormalizedScore(1.0);
            }
            return;
        }

        for (RecallItem item : items) {
            double normalized = (item.getRawScore() - minScore) / range;
            item.setNormalizedScore(normalized);
        }
    }

    // 构建DSL的辅助方法(省略具体实现)
    private SearchRequest buildEntitySearchRequest(QPResult qpResult) { return null; }
    private SearchRequest buildTextSearchRequest(QPResult qpResult) { return null; }
    private SearchRequest buildVectorSearchRequest(float[] queryEmbedding) { return null; }
}
```

## 六、工程落地最佳实践

### 6.1 降级兜底机制

1. 一级降级：实体召回失败 → 保留文本 + 向量召回
    
2. 二级降级：向量召回失败 → 保留实体 + 文本召回
    
3. 三级降级：实体 + 向量都失败 → 纯文本召回
    
4. 四级降级：合并后结果不足 100 条 → 放宽文本召回匹配规则
    

### 6.2 监控指标

- 召回延迟：P50、P95、P99 延迟
    
- 召回数量：每路召回的平均数量、零结果率
    
- 召回质量：NDCG@10、首点击位置、核心文档漏召率
    
- 异常指标：ES 请求失败率、QP 服务失败率
    

### 6.3 调试方法

使用 ES 的`explain`接口查看每个文档的得分构成，快速定位排序问题：

```json
{
  "explain": true,
  "size": 1,
  "query": {
    // 你的查询逻辑
  }
}
```
